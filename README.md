# RBPO — управление разработкой и релизами

## Назначение

REST API для управления программными продуктами, задачами разработки,
пользователями, релизами и проверками перед выпуском.

Приложение использует Spring Boot, Spring Data JPA, Hibernate и PostgreSQL.
Работа с данными выполняется через слой Repository, а бизнес-правила
реализованы в сервисах.

## Модель данных

- **User** — пользователь, который может отвечать за продукт или выполнять задачу.
- **SoftwareProduct** — программный продукт с текущей версией и ответственным пользователем.
- **DevelopmentTask** — задача определённого продукта и версии, при необходимости назначенная пользователю.
- **Release** — релиз определённого продукта с номером, статусом и датой публикации.
- **ReleaseCheck** — проверка конкретного релиза с признаком обязательности и результатом.

Основные связи:
- продукт ссылается на ответственного пользователя;
- задача ссылается на продукт и назначенного пользователя;
- релиз ссылается на продукт;
- проверка ссылается на релиз.

## REST API

CRUD-операции доступны по адресам:

- `/api/users`
- `/api/software-products`
- `/api/development-tasks`
- `/api/releases`
- `/api/release-checks`

## Бизнес-операции

1. `POST /api/development-tasks/{id}/assign` — назначение разработчика на задачу.
2. `POST /api/development-tasks/{id}/ready` — подтверждение готовности задачи.
3. `POST /api/release-checks/{id}/result` — фиксация результата проверки релиза.
4. `POST /api/releases/{id}/approve` — согласование релиза, если задачи готовы и обязательные проверки пройдены.
5. `POST /api/releases/{id}/publish` — публикация согласованного релиза с записью даты и обновлением текущей версии продукта.

Операции проверяют состояние связанных сущностей. Недопустимые переходы
состояний отклоняются, а связанные изменения при публикации выполняются
в одной транзакции.

## Настройка подключения

Создайте в PostgreSQL базу `rbpo_db`, таблицы согласно SQL-схеме проекта
и пользователя `rbpo_app` с ограниченными правами на работу с данными.

Параметры подключения задаются переменными окружения:

- `DB_URL` — URL PostgreSQL;
- `DB_USERNAME` — имя пользователя БД;
- `DB_PASSWORD` — пароль пользователя БД.

По умолчанию URL указывает на `jdbc:postgresql://localhost:5432/rbpo_db`,
а пользователь — на `rbpo_app`. Пароль должен быть задан отдельно.

Секреты не следует хранить в исходном коде или добавлять в Git.

## Запуск

В IntelliJ IDEA запустите `RbpoApplication` через конфигурацию Spring Boot,
предварительно задав необходимые переменные окружения.

Hibernate использует режим `ddl-auto: validate`: приложение проверяет
соответствие JPA-модели существующей схеме БД и не создаёт таблицы автоматически.
